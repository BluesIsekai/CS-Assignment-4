What is Reflected Cross-Site Scripting (XSS)?

Understanding the Mechanics of Non-Persistent Code Injection

Cross-Site Scripting (XSS) is an injection vulnerability that occurs when a web application takes untrusted data from an HTTP request and includes it in an HTML response without proper sanitization or context-aware encoding.

Reflected XSS (Type 1 / Non-Persistent): In reflected XSS, the malicious payload is not stored inside a database. Instead, it is passed within the request itself (commonly in the URL query parameters or form submissions). The server immediately "reflects" that input back into the page response.

Why Variant 2 (Reflected in HTML Context)? In Variant 2, the user's input is reflected directly between standard HTML tags (e.g., inside <div>Search results for: [INPUT]</div>). If an attacker provides markup characters such as <script>, the browser's parser misinterprets the data as executable directives rather than plain string content.

Reflected XSS Attack Lifecycle

1
Attacker Crafts Malicious URL: http://lab.local/vulnerable?q=<script>alert(1)</script>
2
Victim Clicks Link: Browser sends GET request with the payload in query parameters.
3
Server Reflects Unescaped Input: Flask renders response containing the raw un-encoded <script> tags.
4
Browser Executes Injected JavaScript: The victim's browser runs the script under the context of the vulnerable origin!
Academic Objectives

Purpose of This Laboratory Experiment

Designed for cybersecurity students to understand both offensive exploitation mechanics and defensive implementation in modern web applications.

1. Understand the Root Cause

Examine why treating user input as executable code breaks the fundamental security principle of separating instructions from data in browser parsing engines.

2. Verify Output Encoding

Observe how converting characters like < to &lt; forces the browser parser to stay in the Character Reference State, treating payloads purely as literal text.

3. Defense-in-Depth

Explore essential defensive controls including context-aware output encoding, Content Security Policy (CSP), HttpOnly cookies, and safe DOM sinks.
